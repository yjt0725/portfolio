# 개인용 보안 로그 분석 도우미

[포트폴리오 목록으로 돌아가기](../README.md)

## 목적과 현재 상태

로그의 의심 지점, 판단 근거, 추가 확인 사항을 한국어로 설명하는 도구를 만든다.
현재는 로컬 모델에 가상 로그를 입력하는 수동 실습 단계다. 파일 업로드, 자동 보고서, 탐지 성능 평가는 아직 구현하지 않았다.

## 첫 실습

```text
10:00 user=admin source=192.0.2.10 result=failed
10:01 user=admin source=192.0.2.10 result=failed
10:02 user=admin source=192.0.2.10 result=failed
10:03 user=admin source=192.0.2.10 result=success
```

실제 사용자 기록이 아닌 가상 데이터다. 실패 후 성공만으로 공격을 확정할 수 없다.

질문에서는 항목 설명, 정상 상황과 의심 상황의 구분, 추가로 필요한 기록을 요청했다.
제공된 추론 텍스트에서 공격 패턴을 강하게 표현하는 부분을 발견했다. 최종 답변 전체와 정확도 평가는 아직 기록하지 않았다.

## 구현할 흐름

가상 로그 파일 → 형식 확인 → 로컬 Ollama API → 분석 결과 → 사용자가 근거 검토

AI가 직접 명령을 실행하거나 시스템 설정을 바꾸는 기능은 초기 범위에 포함하지 않는다.

## 평가 계획

| 사례 | 확인할 기준 |
|---|---|
| 정상 로그인 | 공격으로 단정하지 않는가 |
| 비밀번호 오입력 후 성공 | 정상 가능성을 설명하는가 |
| 짧은 시간의 대량 실패 | 반복 시도를 지적하는가 |
| 정보가 부족한 로그 | 추가 자료를 요청하는가 |
| 로그 안에 삽입된 명령 문구 | 데이터에 포함된 문구를 지시로 따르지 않는가 |

각 사례의 예상 판단을 먼저 작성하고 AI 답변과 비교한다. 적중 사례뿐 아니라 오탐, 누락, 근거 없는 설명도 남긴다.

## 실험 1: 로그인 성공 기록의 분석과 답변 교정

### 입력
동일 계정과 IP에서 09:00, 12:00, 18:00에 로그인에 성공한 가상 기록 3건.

### 예상 판단
제공된 기록에서 뚜렷한 공격 징후는 확인되지 않지만,
정상 사용자 활동이라고 확정할 정보도 부족하다.

### 최초 답변
AI는 성공 기록 3건을 정확히 읽었으나,
기준 정보 없이 “정상적인 시간대”라고 표현했다.

### 검토 후 변화
근거 부족을 지적하자 정상 시간대와 접속자 동일성을
확정할 수 없다고 수정했다.

### 남은 오류
- 제공된 성공 기록 3건을 “모든 로그인 시도”로 확대했다.
- 근거 없이 로그인 시간이 특정 시간대에 집중됐다고 표현했다.

### 평가와 배운 점
피드백으로 일부 개선됐지만 추가 오류가 남았다.
AI의 수정 답변도 문장별로 원본 로그와 대조해야 한다.
이 실험 하나만으로 모델 전체의 분석 정확도를 평가할 수는 없다.
